# 法人籌碼 — 股價／籌碼／法人／借券 PWA

查詢台股個股**股價、技術面（EMA／RSI／MACD／KD）、籌碼（融資融券／外資持股）、
三大法人買賣超、借券**的個人 PWA。資料來源為 [FinMind](https://finmindtrade.com)
開放資料（源自證交所／櫃買中心公開資訊），分兩段排程由 GitHub Actions 自動抓取：

- **17:30**（台北時間）：股價／技術面／三大法人 — TWSE/TPEx 通常這時候已經
  把當日收盤資料結算完。
- **21:30**（台北時間）：融資融券／借券 — 這類資料公布時間通常比較晚。

兩段各自只抓自己負責的部分，用「合併」而不是「整份覆蓋」寫回
`data/stocks/{code}.json`，晚上那段不會把下午抓到的資料洗掉，反之亦然。

## 訊號分頁：籌碼結構規則式判讀（不是機率模型）

「訊號」分頁把「賣壓/買壓是機制性還是方向性」「套牢的融資有沒有斷頭壓力」「空方是回補
還是加碼」這三個問題，用既有的六類免費資料做成規則式（rule-based）判讀，取代原本得盯著
三大法人、融資、融券、借券四張表格自己心算的動作。這套邏輯不是憑空設計的，是把一次
針對單一股票、單一交易日手動寫的籌碼結構分析，抽象成可以套用在任何股票、任何一天的
通用規則。

### 三個訊號怎麼算

| 訊號 | 用到的資料 | 判讀邏輯 |
| --- | --- | --- |
| 法人結構 | `institutional` 最新一日 + `price.daily` 當日成交量 | 三大法人合計買賣超佔當日成交量比重，以及自營商 vs 外資+投信的絕對值誰大。淨賣超但佔比小（<15%）且自營商主導 → 判讀為「賣壓偏機制性」（例如權證發行商 Delta 避險、造市），計 +1；淨賣超且佔比大或外資投信主導 → 「賣壓偏方向性」，計 -1；淨買超 → +1。 |
| 融資健康度 | `margin`（回看 N 日）+ `price.daily` 對應日收盤價 | 只取回看區間內「融資淨增加」的交易日，用當日收盤價當作近似成交均價，算出加權平均成本，跟現價比較算帳面損益 %；再用「（現價÷估算成本）÷融資成數」估維持率。維持率 ≥150% 記「斷頭壓力低」(+1)，130~150% 記「接近警戒水位」(0)，<130% 記「斷頭壓力高」(-1)。 |
| 券資氣氛 | `margin.shortChange`（融券增減，回看 N 日加總）+ `lending`（借券成交量，僅顯示不計分） | 回看區間融券餘額淨減少（回補）→「空頭回補為主」+1；淨增加（加碼放空）→「空頭增碼為主」-1；打平 → 0。借券成交量只作補充資訊顯示，FinMind 的借券資料集只給當日新成交量，無法拆解「借券賣出」與「借券返還」，所以算不出真正的借券淨增減，不納入計分。 |

三個訊號的分數（-1/0/+1）加總，作為「綜合判讀」的方向：+2 以上「偏多」、+1「略偏多」、
0「中性／訊號不一致」、-1「略偏空」、-2 以下「偏空」。同號愈多代表訊號愈一致，**不是
勝率或機率**。任何一項訊號缺資料時該項計為「資料不足」、不計入加總，畫面上會顯示
「幾項訊號可用」，方便判斷分數的可信度。

### 融資成數與維持率門檻是可調的概念性數字，不是正式規定

- 一般上市/上櫃股票常見融資成數是 6 成，但**注意股、處置股、全額交割股常會被調降融資
  成數、甚至完全停止信用交易**，所以介面上把融資成數做成可調參數（5/6/7 成），不是
  寫死 6 成——這也是為什麼原本手動分析的那檔處置期股票特別需要留意這件事。
- 150%／130% 這兩個門檻是抓「業界常聽到的警戒/追繳水位」概念，**不是任何特定券商的
  正式規定**，實際斷頭／追繳線每家券商可能不同，這欄位只能當方向參考，不能拿來精算
  真正會不會被斷頭。

### 這個分頁刻意沒做的兩件事

1. **券商分點買賣超** — 跟前面「涵蓋範圍」提到的一樣，FinMind 免費方案沒有這個資料集，
   所以「是哪個分點在買/賣、有沒有特定主力在低接」這件事做不到，只能看三大法人的組成
   當替代訊號。
2. **內外盤比（買方主動 vs 賣方主動）** — 本工具沒有串接任何提供逐筆內外盤資料的來源，
   這項也做不到。

如果你需要以上兩項，得靠人工去看券商 App 的即時分點/內外盤，或另外找付費資料源；這個
分頁只是把「用免費資料能算出來的部分」自動化、標準化到任何一檔股票都能套用，不是要
取代分點/內外盤判讀。

### 免責提醒

跟其餘分頁一樣：資料僅供參考，不構成投資建議。這個分頁多一層要提醒的地方是——它是
「規則式試算」，用固定公式和門檻把免費資料轉成偏多/偏空的標籤，**不是根據歷史勝率
回測校準過的模型**，標籤一致不代表準，標籤不一致也不代表這就是雜訊，請當作幫你把
原始數字組織起來的輔助工具，不是自動找買賣點的訊號燈。

## 報告分頁：固定章節格式的每日籌碼結構報告

「報告」分頁把「訊號」分頁背後同一套運算（三大法人結構、融資健康度、券資氣氛）
重新排版成固定六個章節的報告格式，另外加上量能／KD／MACD／RSI 技術面整理，
單位跟門檻邏輯完全跟「訊號」分頁共用（回看天數、融資成數也是同一組設定，在
「訊號」分頁調整，兩邊會一起變）：

一、基本盤勢整理（收盤價／漲跌幅／成交量；內外盤標示「無法取得」）
二、技術線型分析（量能／KD／MACD／RSI）
三、券商分點軌跡（自動抓取做不到，改提供「對話式」半自動：官方買賣日報表
　　查詢系統連結＋一鍵打包本 App 全部數據成分析請求，使用者截圖分點頁後
　　連同請求貼給 Claude 交叉分析——詳見下方「分點分析請求」說明）
四、數據總整理（三大法人賣方/買方結構、融資融券每日增減與累計餘額、
　　融資的「估算加權成本區」——用回看期間內融資淨增加當日的收盤價加權估算，
　　**不是**真實逐筆成交均價，跟券商實際計算會有落差；借券只列得出「當日新
　　成交量」，算不出加權成本區，不會硬湊）
五、今日數據觀察（列出各項訊號各自的解讀，不收斂成單一結論，不是機率/勝率）
六、後續關注重點（列出可對照的均線位階，不做「明日情境」式的走勢預測）

第三、五、六節刻意跟一般手寫籌碼分析報告的常見寫法不一樣，這是有意的設計：
分點軌跡沒有資料來源、無法取得就照實寫「無法取得」，不會拿其他欄位湊一個看
起來像的替代數字；「今日盤勢的核心假說」跟「明日情境一/二/三」這種把數據
收斂成單一定論、對次一交易日走勢做具體推演的寫法，不管有沒有標示機率，本質
上都是一種預測而不是數據整理，所以這裡改成列出各項數據各自的解讀方向、以及
可以拿現價對照的技術位階，不幫你下結論。

### 分點分析請求（對話式 workaround）

分點資料的兩條正規取得路徑都不適合這個免費靜態 App：FinMind 的
`TaiwanStockTradingDailyReport` 官方文件明確標注 Sponsor（付費）限定；證交所
（bsr.twse.com.tw）與櫃買中心的官方買賣日報表查詢系統雖然免費，但查詢需要輸入
驗證碼，那是刻意擋自動化的設計，用程式繞過它在技術上跟使用條款上都不妥當。

所以改走「人做人擅長的、機器做機器擅長的」半自動流程：報告分頁第三節有一顆
「複製分點分析請求」按鈕，按下去會把這檔股票當日所有 App 已算好的數據（盤勢、
三大法人、融資融券含估算成本與維持率、借券、技術指標）打包成一段結構化文字
複製到剪貼簿；使用者到官方查詢系統（按鈕上方有依上市/上櫃自動對應的連結）或
自己券商 App 把分點頁截圖，然後打開 Claude、貼上文字＋附上截圖，由 Claude 讀圖
並跟 App 數據交叉分析。請求文字的最後一條指示明確要求：講不出來的直說做不到，
不要腦補——分析品質的底線跟這個 App 其他部分一致。

## 架構

```
watchlist.json          常駐追蹤的股票代號（預設 ["8069"] 元太科技）
scripts/fetch-data.mjs  抓資料＋算技術指標＋彙整月/季線的 Node.js 腳本
.github/workflows/      每日 17:30／21:30 分兩段排程執行上面的腳本，把結果 commit 回 repo
data/                   抓下來的資料（stock-list.json + stocks/{代號}.json）
index.html / app.js / style.css   前端 PWA（股價／籌碼／法人／借券 分頁）
```

前端是純靜態網頁，沒有建置流程，GitHub Pages 開啟後就能直接用。

`data/stocks/{代號}.json` 內容結構：

```json
{
  "code": "8069",
  "updatedAt": "...",
  "price": { "daily": [...], "monthly": [...], "quarterly": [...] },
  "technical": [{ "date": "...", "ema5": ..., "ema20": ..., "ema60": ..., "rsi14": ..., "macd": ..., "macdSignal": ..., "macdHist": ... }],
  "valuation": [{ "date": "...", "per": ..., "pbr": ..., "dividendYield": ... }],
  "institutional": [{ "date": "...", "foreign": ..., "trust": ..., "dealer": ..., "total": ... }],
  "margin": [{ "date": "...", "marginBalance": ..., "marginChange": ..., "shortBalance": ..., "shortChange": ... }],
  "shareholding": [{ "date": "...", "foreignSharesRatio": ... }],
  "lending": [{ "date": "...", "volume": ..., "avgFeeRate": ... }]
}
```

## 設定步驟

1. **建立 GitHub repo**，把這個資料夾所有檔案上傳進去。
2. **啟用 GitHub Pages**：repo → Settings → Pages → Source 選
   `Deploy from a branch` → Branch 選 `main` / `(root)` → Save。
3. **（建議）填入 repo 網址**：打開 `config.js`，把 `repoUrl` 填成你的 repo
   網址，用於「查無快取資料」時的提示訊息。
4. **（建議）申請 FinMind 免費 token**：到 finmindtrade.com 免費註冊拿
   token，到 repo → Settings → Secrets and variables → Actions → New
   repository secret，新增 `FINMIND_TOKEN`。每檔股票現在要抓 6 個資料集，
   有 token 額度是 600 次/小時，沒有是 300 次/小時，追蹤股票一多建議還是
   設一下。
5. **手動跑一次**：repo → Actions → 分別把 `Update market data (afternoon —
   price/technical/institutional)` 跟 `Update market data (evening —
   margin/lending)` 都手動 Run workflow 一次。跑完後 `data/` 底下會出現
   完整資料。之後每個交易日台北時間 17:30 跟 21:30 會分別自動再跑一次
   （各自只抓自己負責的那一半，不會互相覆蓋）。
6. **iPhone 安裝**：Safari 開啟 Pages 網址 → 分享 → 「加入主畫面」。

## 查任一檔（不在 watchlist 的股票）

App 會直接從瀏覽器即時呼叫 FinMind，查**完整六項資料**（股價/技術面、
PER/PBR、法人動態、融資融券、外資持股、借券），跟常駐清單股票看到的內容
一樣完整，只是這次查詢不會被存起來，離開頁面或關掉後要重新查。這需要
FinMind 允許瀏覽器跨網域請求，無法 100% 保證每項都成功——如果某一項資料
剛好抓不到，該分頁會顯示暫無資料，不影響其他分頁。

查到即時資料後，畫面上會多一個「＋ 加入常駐清單」按鈕，用意是把這檔股票
**快取起來**，下次開啟秒開、也能離線查詢（跟即時查詢比，差別在速度和
離線能力，不是資料完整度）。點下去有兩種結果：

- **有設定 GitHub token**：直接幫你把代號寫進 GitHub 上的 `watchlist.json`。
- **沒有 token**：把更新後的完整清單複製到剪貼簿，並給你 `watchlist.json`
  的編輯頁連結，你手動貼上、Commit 即可。

### 常駐清單記錄

頂部搜尋框下方有個「常駐清單」按鈕，點開會列出目前 `watchlist.json`
裡的所有股票，包含加入時間（用 App 加入的會記錄時間；手動編輯或原始
`["8069"]` 這種沒有時間戳記的項目會顯示「原始清單」）。點清單裡任一項
可以直接跳去查看該股票。

`watchlist.json` 的項目格式現在支援兩種混用：

```json
[
  "8069",
  { "code": "6526", "name": "達發", "addedAt": "2026-07-11T01:23:45.678Z" }
]
```

純字串（舊格式、手動加的）跟物件（App 自動加的，含名稱與時間）可以並存，
`scripts/fetch-data.mjs` 兩種都認得。

### 設定 token（只需做一次，非必要）

1. GitHub 右上角頭像 → **Settings** → 左側最下面 **Developer settings**
2. **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
3. Repository access 選 **Only select repositories**，選你這個 repo
4. Permissions → **Repository permissions** → **Contents** 設為 **Read and write**，其他都不用動
5. 產生後複製 token，貼進 App 裡「＋ 加入常駐清單」跳出的欄位

這個 token **只會存在你這支手機瀏覽器的 localStorage 裡**，不會傳到我或
任何第三方；但它終究是一組有寫入權限的憑證，存在瀏覽器裡代表任何能碰到
這支手機的人理論上都碰得到它。如果不放心，略過這步驟，全程用複製貼上
